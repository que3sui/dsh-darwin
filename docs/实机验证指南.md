# 实机验证指南（跟着敲就行）

> 目的：在真实 DSH 环境里跑通 dsh-darwin 全链路，核销两个 `dsh-adapter.ts` 里的 `TODO(verify)`。
> 原则：**每一步都有"预期看到什么"；只要实际输出和预期不一致，把完整日志贴给维护者（或开 issue）——那就是最有价值的反馈。**

---

## 0. 前置条件（一次性）

| 需要 | 检查命令 | 说明 |
|---|---|---|
| Node.js ≥ 22.19 | `node -v` | DSH CI 覆盖 22.19 / 24 / 26 |
| DeepSeek API Key | — | platform.deepseek.com 充值获取，**先小额**（预览期 harness 本身较费 token） |
| git | `git --version` | |
| 一个试验田目录 | — | **别用重要项目**，建个空目录专门做验证 |

## 1. 安装并启动 DSH

```bash
npm install -g @deepseek-ai/dsh
dsh --version        # 预期：0.1.1-rc.2 或更新
```

配置 API Key：

```bash
# Git Bash / macOS / Linux
export DEEPSEEK_API_KEY=sk-你的key
# Windows PowerShell
$env:DEEPSEEK_API_KEY = "sk-你的key"
```

建试验田并启动：

```bash
mkdir dsh-lab && cd dsh-lab
git init
dsh web        # 具体子命令以 `dsh --help` 为准；能进入对话/界面即成功
```

✅ 预期：能和 agent 正常对话（先随便聊一句确认模型通了）。

## 2. 获取 dsh-darwin（含依赖安装）

```bash
git clone https://github.com/que3sui/dsh-darwin.git
cd dsh-darwin
pnpm install     # 必须！注意是 pnpm：DSH 原位加载插件源码，zod 依赖要在位；
                 # npm 不支持 lab 包的 workspace:* 协议会报 EUNSUPPORTEDPROTOCOL。
                 # 没有 pnpm 的话：npm i -g pnpm 或 corepack enable
cd ..
```

## 3. 安装两个插件

```bash
# --profile 是必填项（实测 0.1.1-rc.2）：dsh web 启动对应 web profile
dsh plugin --profile web add ./dsh-darwin/packages/sentinel
dsh plugin --profile web add ./dsh-darwin/packages/forge
```

然后**重启 DSH**（回到 dsh-lab 目录再启动）。

✅ 预期在启动日志里看到两行：

```
[dsh-sentinel] 已注册 darwin_scan / darwin_report
[dsh-forge] 已注册 darwin_forge / darwin_promote / darwin_rollback
```

⚠️ **三个关键诊断点**（这是我们最想知道的）：

| 若看到 | 含义 | 动作 |
|---|---|---|
| `无 ctx.storageDomain，使用内存工单库` | 共享域服务没探测到，功能可测但重启丢工单 | 贴日志 |
| `storageDomain.open 失败，回退内存` | 官方 DomainSpec 形状与假设不符 | **完整贴日志**（这是要核销的 TODO） |
| `找不到 ctx.sessionQuery` | sentinel 起不来 | **完整贴日志** |

## 4. 全链路验证（在 DSH 对话里依次说）

先在试验田里让 agent 干点活（最好包含一次会失败的任务，制造"问题信号"），然后：

| # | 你说 | 预期输出 |
|---|---|---|
| 1 | 调用 darwin_scan 工具 | `扫描完成：N 个会话，M 个信号 / 新建工单 X，更新 Y` |
| 2 | 调用 darwin_report | 按严重度排序的会话体检报告 |
| 3 | 调用 darwin_forge | `候选已生成（draft）… 候选 id: cnd-xxxx` |
| 4 | 调用 darwin_promote，candidateId 填上面的 id，confirm 设为 true | `已晋级 → ./.dsh/skills/<技能名>/SKILL.md（热重载生效）` |
| 5 | （终端）`cat ./.dsh/skills/<技能名>/SKILL.md` | 文件存在，含 `---` frontmatter 和"行为指引"正文 |
| 6 | 调用 darwin_rollback，skillName 填技能名，confirm true | `已回滚（removed-file）…`，文件消失 |

✅ 1-6 全过 = 链路完整。

## 5. （可选进阶）核销 adapter TODO

## 已知可能的卡点（按概率排序）

1. ~~`dsh plugin add` 要求 `--profile`~~ → 已实测确认必填，用 `--profile web`（见第 3 步）；
2. ~~无扩展名导入 `ERR_MODULE_NOT_FOUND`~~ → 已修：DSH 用 Node 原生 ESM 加载 TS 源码，相对导入必须带 `.ts`；插件现为自包含（protocol 已内联为 `src/protocol.ts`），外部依赖仅 `zod`；代码避免了参数属性等 strip-only 不支持语法。clone 后务必 `pnpm install`（npm 不支持 workspace:* 协议）；
3. Windows PowerShell 找不到 `dsh` → npm 全局目录被 conda 初始化钩子从 PATH 挤掉，在 profile 末尾补 `$env:PATH += ";" + (Join-Path $env:APPDATA "npm")`；
4. 工具调用方式：DSH 里模型调用工具的说法可能是"使用 xxx 工具"或斜杠命令，以你版本的交互习惯为准，目标只是让模型触发 `darwin_*` 工具。
